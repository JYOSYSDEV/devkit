# 人間ゲートと判断依頼の確認を手伝う

対象: $ARGUMENTS（指定がなければ `pnpm -s devkit status --json` の `waitingFor` から）

人間ゲートは2種類です。相手によって話し方を変えてください。

| ゲート | 相手 | 確認すること | 話し方 |
| --- | --- | --- | --- |
| 業務ゲート | 業務担当者 | 仕様どおりの業務ができるか（画面・操作・業務ルール・権限表） | 技術用語を使わない。画面と操作の言葉で |
| 技術ゲート | 標準オーナー | 標準の外の判断（外部接続・個人情報・データモデル・安全の中心・本番リリース） | ルール ID・根拠・リスクを示す |

## 手順

1. 状態を読む: `pnpm -s devkit status --json`。マイルストーンの `required`（必要な承認者）・`flags`（変更内容から自動で見つけた確認事項）・`release`（リリース前検査）・`finalReview`（最終レビュー）を確かめる。
2. 確認資料を作り直す: `pnpm -s devkit gate <ID>` → `.devkit/gates/<ID>.html`（できたこと・受入基準・判断してほしいこと・画面写真を1ファイルにまとめたもの。そのままメールやチャットに添付できる）。開けない環境なら `.devkit/cache/screens/<ID>/` の画像を Read で見て説明する。
3. 相手に合わせて要約する。

**業務担当者向け**（5〜10行）:
```
<ID>「<名前>」ができました。確認をお願いします。

できたこと: （作業ごとの要約を業務の言葉で）
見てほしい画面: （画面名と操作。確認資料の写真）
判断してほしいこと: （業務のフラグ。例: 権限表が変わった → 新旧を表で）

よければ端末で: pnpm devkit approve <ID> --role 業務
直してほしい点があれば、具体的に教えてください（差し戻しの文に直します）。
```

**標準オーナー向け**:
- フラグの内容と該当箇所（新しい接続先 → コードの場所と、`docs/profile.json` の externalHosts への登録が要ること。個人情報 → 列名と、閲覧権限・ログ・保持期間。データモデル・安全の中心 → 差分）
- 独立レビュー（作業ごと）と最終レビューの判定
- 人が確かめる標準の項目（`docs/standard/rules.json` の `"check": "human"`。リリースなら運用レベル別の必須事項）
- リリースのマイルストーンなら、リリース前検査（`pnpm standard:release`）の結果。技術の承認には合格が要る

4. 返事を、人が端末で実行するコマンドに直して示す（**Claude からは実行できない**。フックとコマンド自身が止める）:

| 返事 | 端末で実行するコマンド |
| --- | --- |
| 「承認します」 | `pnpm devkit approve <ID> --role 業務`（標準オーナーなら `--role 技術`） |
| 「〇〇を直して」 | 指摘を **確かめられる形** に言い換えて本人に確認してから `pnpm devkit reject <ID> --role 業務 --note "<指摘>"`（差し戻せるのは、そのマイルストーンの承認者の役割だけ） |
| 判断依頼への回答 | `pnpm devkit answer <ノード> --role <依頼の種別> --request <依頼の ID> --note "<回答>"`（依頼は `.devkit/requests/<ノード>.md`。先頭の「判断依頼」と「種別」をそのまま使う。種別の役割の人だけが回答でき、ほかの役割の回答は断られる） |
| 再計画の案を認める | `pnpm devkit proposal accept <案のID> --role 技術`（案は `.devkit/proposals/<ID>.json`。承認・却下できるのは、`pnpm devkit status` に出る確認者の役割だけ） |
| 外部接続を認める | 本人が `docs/profile.json` の externalHosts に接続先を足してコミットし、承認する |
| 標準の例外を認める | `devkit-standard-exception`（標準オーナー） |

承認は、確認した版（検証したコミット）に紐づきます。承認する人は `docs/profile.json` の owners と照合されます（代理なら `--delegate-of <本人> --note "<理由>"`）。判断は `docs/decisions.md` に自動で残ります。

承認がそろったら、ランナーが止まっていれば `pnpm devkit run`（`devkit-run`）で続きを進める。

## 注意

- 承認する本人の代わりに承認しない。リリースの技術承認を `--force` で通すのは、標準オーナー本人が理由を `--note` に書く場合だけ。
