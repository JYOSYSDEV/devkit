# 社内標準の改訂案をまとめる

標準は使いながら育てます。AI が止まった理由や人が下した判断は、個別に解決して終わりにせず、次の案件で同じことが起きないよう標準・雛形・devkit に反映します。

## 集める材料（この案件の中）

- `docs/decisions.md` — 人の判断（計画の承認、人間ゲートの承認・差し戻し、判断依頼への回答、例外）
- `docs/exceptions.json` と `docs/adr/` — 承認された例外とその理由
- `.devkit/progress.md` — 停止・不合格・再計画、AI が自分で決めたこと（「判断:」）
- `.devkit/state.json` — 作業ごとの試行回数と履歴（機械検証の不合格の理由、レビューの指摘）
- `.devkit/reports/` — 実行のまとめ
- `.devkit/learnings.md`、`.devkit/diagnosis/` — 学んだこと、不調の診断
- `.devkit/proposals/` — 人の確認に回った再計画の案

## 分類のしかた

| 起きたこと | 反映の候補 |
| --- | --- |
| 同じ依存・技術の例外が繰り返し出る | 許可リスト（`docs/standard/dependencies.json` の preApproved）に追加 |
| AI が標準の解釈に迷って止まった・間違えた | ルールの文言を具体化、雛形を追加 |
| レビューで同じ指摘が繰り返し出る | review のルールを auto（機械の検査）にできないか検討 |
| 機械検証で同じ不合格が繰り返し出る | goal の書き方（goal-rules.md）・雛形・CLAUDE.md の改善 |
| 人が業務ゲートで同じ種類の差し戻しをした | 聞き取りの項目・仕様書のテンプレートに追加 |
| 環境の問題で止まった | 展開手順・前提条件の追記 |
| 雛形・devkit のバグ | テンプレート・プラグインの修正 |

## 出力

`docs/standard-feedback-<YYYY-MM-DD>.md` に次の形式で書き、標準オーナーに渡す（プラグインのリポジトリへの提案の下書き）。

```markdown
# 社内標準・devkit 改訂の提案（案件: <名前>、devkit <版>、標準 <版>）

## まとめ（3行）
## 提案
### 1. <タイトル>
- 根拠: <起きたこと。decisions.md の行・progress.md の行・回数>
- 対象: <ルール ID / ファイル>
- 変更案: <具体的な文言・許可リストの追加・新しい検査>
- 期待する効果: <止まる回数が減る、など>
## 標準の問題ではなかったもの（参考）
```

案件の `docs/standard/` は書き換えない。標準の改訂はプラグインのリポジトリで標準オーナーが行い、新しい版として配布する（各案件は `/devkit:devkit-update` で取り込む）。
