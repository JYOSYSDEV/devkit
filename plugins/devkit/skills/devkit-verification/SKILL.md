# 完了を言う前の検証

**核心:** 主張の前に証拠。いつでも。

## 鉄則

```
その場で実行した検証の証拠なしに、完了を主張しない
```

このメッセージの中で検証コマンドを実行していなければ、通ったとは言えない。

## 確かめ方（主張の前に毎回）

1. **特定する:** この主張を証明するコマンドは何か
2. **実行する:** そのコマンドを、省略せず、今あらためて実行する
3. **読む:** 出力を最後まで読み、終了コードと失敗の件数を確かめる
4. **照らし合わせる:** 出力は主張を裏づけているか
   - いいえ → 実際の状態を、証拠とともに伝える
   - はい → 主張を、証拠とともに伝える
5. **そのあとで** 主張する

どれかを飛ばしたら、それは検証ではない。

## 主張と、必要な証拠

| 主張 | 必要な証拠 | 足りないもの |
| --- | --- | --- |
| テストが通る | `pnpm test` の出力で失敗 0 件 | 前回の実行結果、「通るはず」 |
| lint・型が通る | `pnpm verify` の終了コード 0 | 一部のファイルだけの確認 |
| ビルドできる | `pnpm build` の終了コード 0 | lint が通ったこと |
| 画面の流れが動く | `pnpm verify:full`（E2E を含む）の終了コード 0 | 単体テストが通ったこと |
| 不具合が直った | 元の症状を再現するテストが今は通る | コードを変えたこと |
| 回帰テストが効いている | 修正を戻すと落ち、戻すと通ることを確かめた | テストが1回通ったこと |
| サブエージェントが完了した | `git diff` と検証コマンドで自分が確かめた | エージェントの「成功しました」 |
| 受け入れ基準を満たした | 仕様書の AC を1つずつ照らし合わせ、対応するテストが通っている | テストが全部通ったこと |

## 危険信号（見つけたら止まって検証する）

- 「〜のはず」「たぶん」「〜と思われる」と書こうとしている
- 検証の前に「できました」「完璧です」と言おうとしている
- 検証せずにコミット・push・PR 作成・完了の報告（`status: implemented`）をしようとしている
- エージェントの成功報告をそのまま信じている
- 一部だけ確かめて全体を言おうとしている
- 「今回だけ」と考えている

## 言い訳と現実

| 言い訳 | 現実 |
| --- | --- |
| 「もう動くはず」 | 実行する |
| 「自信がある」 | 自信は証拠ではない |
| 「lint は通った」 | lint はビルドではない |
| 「エージェントが成功と言った」 | 自分で確かめる |
| 「一部確かめたから十分」 | 一部では何も証明できない |

## いつ使うか

次の前には必ず:

- 完了・成功を表す言葉（言い換え・ほのめかしも含む）
- コミット、PR 作成、作業の完了報告（ランナーへの構造化出力）
- 次のタスク・次のノードへ進むこと
- 作業をサブエージェントに任せたあとの報告
