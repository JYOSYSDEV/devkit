# devkit の仕組み: 計画 → ランナー → 人間ゲート

Claude Code に「作って」と頼んだあと、人が毎回「続けて」と言わなくても、夜のあいだも、最後まで進むようにするための仕組みです。人が判断するのは、計画の承認、要所の承認（人間ゲート）、AI が決められないことへの回答、最後のリリース判断だけです。

```
① 要件・計画  AI が聞き取り → 仕様書・案件プロファイル・マイルストーン・作業の依存グラフ・goal → 機械の検査 → 別の AI のレビュー
               → 人（業務担当者・標準オーナー）が端末で承認（計画のハッシュに紐づく）
② ランナー    pnpm devkit run（コード）が、次にやることを選ぶ
③ 作業ごと    リポジトリの外の作業ディレクトリで AI が実装（Bash はサンドボックス） → ランナーが取り込んでコミット → ランナーが機械検証（検証コマンドはコンテナの中）
               → 別の AI がレビュー → 証拠を対象コミットに紐づける（並列に実行）
④ 統合        クリーンにマージできるものだけ順に統合 → 統合後の機械検証（失敗なら取り消し）→ 作業を完了に
⑤ 再計画      止まった作業は AI が原因を調べて案を出し、ランナーが「承認済みの範囲か」を機械で分類して入れる
⑥ マイルストーン  全体検証（ビルド・E2E・受入基準の照合）→ 変更内容から承認者を決める → 人間ゲート
⑦ 完了        最後のマイルストーンでリリース前検査と最終レビュー → 人の承認 → 完了（リリースとデプロイは人）
```

## 誰が何を決めるか

| 判断 | 決めるもの | どこにあるか |
| --- | --- | --- |
| 何を・なぜ作るか、業務ルール、権限 | 業務担当者 | 仕様書 `docs/spec/<slug>.md`、業務ゲート |
| 標準の外の判断（外部接続・個人情報・データモデル・本番リリース・例外） | 標準オーナー | 技術ゲート、`docs/exceptions.json` |
| どう作るか（社内標準の範囲で） | AI | 実装（implementer）、再計画の案（replanner） |
| 合格か不合格か、次に何をするか、止まるか | ランナー（コード） | `scripts/devkit/`。AI の自己申告では決まらない |

AI が判断に関わるのは、実装・レビュー・再計画の案の3つだけです。合否、統合、状態の更新、承認者の決定、止める判断は、すべてランナーのコードが行います。

## 隔離

- **検証はコンテナの中**: 対象のコミットを git の外の普通のフォルダに取り出し、コンテナ（Docker か Podman）の中で、依存のインストール（ネットワークあり）と検証コマンド（`--network none`・root 以外・読み取り専用のルート）を実行します。コンテナから見えるのは取り出したフォルダとキャッシュだけで、本体のリポジトリ・承認・計画には届きません。結果のファイルは、リンクをたどらずに読みます。
- **AI の作業はリポジトリの外**: 実装担当の作業ディレクトリ、レビュー・再計画・最終レビュー用の取り出しは、リポジトリの外の作業場所（既定 `~/.cache/devkit/<案件>/work`）に作ります。AI の Bash は Claude Code のサンドボックスの中で動き、作業ディレクトリの外に書き込めず、ネットワークも使えません（`aiSandbox: required`）。ガードはリポジトリ本体のもの（作業ディレクトリの写しではない）を使います。
- **改ざんの検出**: ランナーの実行中、承認・計画・判断の記録・devkit 自身のファイルが、ランナー自身と人のコマンド（`.devkit/journal.jsonl` に記録が残る）以外から変わったら、止まってコミットしません。隔離を補うもので、置き換えではありません。

## ファイル

| ファイル | 中身 | 書くもの |
| --- | --- | --- |
| `.devkit/graph.json` | 計画（マイルストーン・作業・依存・担当パス・受入基準・goal・承認者・制限） | kickoff と再計画（承認後の変更は、承認済みの範囲の自動再計画か人の承認だけ） |
| `.devkit/mission.md` | ミッションの目的・完了の定義・前提 | kickoff |
| `.devkit/state.json` | 実行の状態（作業・マイルストーンの状態、試行回数、ラウンドごとの結果） | ランナーだけ |
| `.devkit/controls.json` | 人の決定（計画の承認、記録したゲート、承認、差し戻し、回答、再計画の案の承認、一時停止、サイクル上限） | devkit のコマンドだけ（人の操作は端末から） |
| `.devkit/journal.jsonl` | 人のコマンドが書いたファイルと、その内容のハッシュ（ランナーが改ざんと区別するため） | devkit のコマンドだけ |
| `.devkit/config.json` | ランナーの設定（AI の権限モード・検証の隔離・AI のサンドボックス・作業場所） | 人が手で（Claude は編集しない） |
| `.devkit/evidence/` | 合格した作業の証拠（対象コミット・機械検証・レビュー） | ランナーだけ |
| `.devkit/progress.md` | 出来事と、AI が自分で決めたこと（「判断:」） | ランナー |
| `.devkit/reports/` | 実行のまとめ（朝のまとめ） | ランナー |
| `.devkit/requests/`・`.devkit/proposals/` | 判断依頼、人の確認が要る再計画の案 | ランナー |
| `.devkit/run.json`・`.devkit/status.html` | ランナーのハートビートと状況ページ（コミットしない） | ランナー |
| `.devkit/reports/tamper-<時刻>.md` | 保護されたファイルの改ざんを検出して止まったときの記録 | ランナー |
| `docs/decisions.md` | 人の判断の記録（判断者・日時・対象のコミット・内容） | devkit のコマンドだけ |
| `docs/profile.json` | 案件プロファイル（担当者・運用レベル・個人情報・認証・外部接続・リリース状態） | kickoff、標準オーナー |

## 承認は計画の内容とコミットに紐づく

- 計画の承認は、graph.json・仕様書・mission.md をまとめたハッシュに紐づきます。承認の後に計画を書き換えると、ランナーは起動しません。例外は2つです: ランナーが「承認済みの範囲」と分類した自動の再計画（記録が残る）と、人が承認した再計画の案。
- マイルストーンの承認は、全体検証をしたコミットに紐づきます（コミットに紐づかない承認は数えません）。前のマイルストーンが差し戻されて開き直ったら、後ろの検証済み・承認済みのマイルストーンは検証からやり直します。完了の前に、リリースの検証をした版と今のコードが同じかを照合します。
- 承認・差し戻し・回答・再計画の案の承認・サイクル上限の追加は、人が端末で実行するコマンドだけが受け付けます。Claude とランナーの AI からは実行できません（コマンド自身とフックが止める）。承認した人が `docs/profile.json` の担当者かも照合します（代理は明示する）。

## 2段の繰り返しと止まる条件

| 段 | 単位 | 上限 | 上限に達したら |
| --- | --- | --- | --- |
| ラウンド | 1回の試行の中の「実装 → 機械検証 → レビュー」 | `limits.maxRounds` | 作業を要再計画にする |
| 試行 | 作業の作り直し（新しい統合先から） | `limits.maxAttempts` | 要再計画 |
| 再計画 | マイルストーンごとの再計画の回数 | `limits.maxReplans` | 停止（人が原因を確かめる） |

ほかに止まる条件: 人の判断待ちだけが残った、一時停止（`pnpm devkit pause`）、サイクル上限（増やせるのは人）、2回続けて進捗がない、`--until`・`--max-hours`・`--max-cost-usd`、環境の問題（ログイン切れ・コンテナのエンジン・サンドボックスなど。試行に数えない）、保護されたファイルの改ざんの検出。最終レビューの修正が `limits.maxFinalFixRounds` 回で直らないときは、指摘を残したまま標準オーナーの判断（技術ゲート）に回します。止まったら通知し、実行のまとめを書きます。

## 夜間の無人実行と状態の確認

- `pnpm devkit run --until 07:00 --detach` で、セッションを閉じても動きます。常時動く機械で回します。
- 状況は、別の端末から `pnpm devkit status`（ランナーの生死・最終応答・誰の番か）、`.devkit/status.html`、通知（`DEVKIT_NOTIFY_*`）、朝の `.devkit/reports/` で分かります。
- ランナーが落ちても、次の起動で中断した作業を照合して続けます（途中のマージは取り消してやり直し、途中の作業は同じブランチの続きから）。

## 見張り（/loop）

人がセッションを開いているときの案内役です（`.claude/loop.md`）。人の判断待ちの案内、ログの要約、PR の CI とレビューの要約を行います。止める・承認するのは見張りの仕事ではありません。夜間の無人実行は見張りに頼りません。

## 作業の作法との関係

ランナーが「何をどの順で進め、合格をどう決めるか」を受け持つのに対して、1つの作業の中で「どう作るか」の作法（テスト駆動、デバッグ、完了前の検証、レビューの観点、要件の聞き出し）は devkit のスキルとエージェントが受け持ちます（`practices.md`）。
