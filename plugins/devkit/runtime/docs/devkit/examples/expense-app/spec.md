# 経費精算システム 仕様書（記入例）

- slug: `expense-app`

## 1. 目的と利用者

紙と Excel で行っている経費精算を Web 化し、承認待ちの滞留と経理の転記作業をなくす。

| 役割                 | 人数の目安 | できること                             |
| -------------------- | ---------- | -------------------------------------- |
| 申請者               | 300人      | 経費の申請、自分の申請の確認・取り消し |
| 承認者（課長・部長） | 40人       | 自部署の申請の承認・差し戻し           |
| 経理                 | 5人        | 承認済み申請の CSV 出力                |

## 2. スコープ

- 対象: 申請・承認・CSV 出力・社内 SSO ログイン
- 対象外: 会計システムへの自動連携、領収書の OCR、モバイルアプリ

## 3. 機能要件

- **FR-1** 申請者は日付・金額・科目・目的を入力して申請できる
- **FR-2** 承認者は自部署の申請を承認または差し戻しできる
- **FR-3** 経理は期間を指定して承認済み申請を CSV で出力できる
- **FR-4** 社員は社内 SSO（OIDC）でログインする

## 4. ビジネスルール

- **BR-1** 金額は 1 円以上 1,000,000 円以下の整数。0 円と 1,000,001 円は拒否する
- **BR-2** 100,000 円以上は課長承認のあと部長承認も必要。99,999 円は課長承認だけで承認済みになる
- **BR-3** 申請者が取り消せるのは「申請中」の間だけ。承認が1つでも付いたら取り消せない
- **BR-4** CSV は UTF-8（BOM 付き）、列は 申請ID, 申請日, 申請者, 科目, 金額, 承認日

## 5. データモデル

| テーブル  | 主な列                                                                                                   |
| --------- | -------------------------------------------------------------------------------------------------------- |
| users     | id, email, name, email_verified, image, department_id, role（applicant / manager / director / accounting）, created_at, updated_at。Better Auth の user として使う |
| expenses  | id, applicant_id, date, amount, category, purpose, status（submitted / approved / rejected / cancelled） |
| approvals | id, expense_id, approver_id, step（manager / director）, decision, decided_at                            |
| sessions / accounts / verifications | Better Auth が使う管理用のテーブル（ログインのセッション、OIDC の連携情報、確認用のトークン） |

## 6. 画面と API

| 種類 | パス                        | 内容                         | 使う役割 |
| ---- | --------------------------- | ---------------------------- | -------- |
| 画面 | `/expenses`                 | 自分の申請一覧・新規申請     | 申請者   |
| 画面 | `/approvals`                | 承認待ち一覧・承認・差し戻し | 承認者   |
| API  | `GET /api/export?from=&to=` | CSV 出力                     | 経理     |

## 7. 受け入れ基準

- **AC-1** 申請すると自分の一覧に「申請中」で表示される
- **AC-2** BR-1 の範囲外の金額は、エラーメッセージとともに拒否される
- **AC-3** 申請中の申請は取り消せ、承認が付いた申請は取り消せない（BR-3）
- **AC-4** 課長は自部署の申請だけを承認待ち一覧で見られる
- **AC-5** 99,999 円の申請は課長承認で承認済み、100,000 円の申請は部長承認待ちになる（BR-2）
- **AC-6** 差し戻すと申請者の一覧で「差し戻し」と表示される
- **AC-7** 経理は期間指定で承認済み申請だけを BR-4 の形式で出力できる
- **AC-8** 経理以外が CSV 出力 API を呼ぶと 403
- **AC-9** 未ログインで画面を開くとログイン画面に移る
- **AC-10** 申請 → 課長承認 → 部長承認 → CSV 出力の一連の流れが画面から行える

## 8. 前提と未決事項

- 前提: 部署は1階層。部長は部署ごとに1人
- 前提（自分の判断）: 認証用のテーブル・環境変数・「ログイン中の利用者」の型は基盤（N1）で決め、SSO のノード（N5）はその形のまま接続部分だけを作る。画面のノード（N2〜N4）は N5 を待たずに作れる
- 前提（自分の判断）: E2E のログインは、テスト用の DB（pglite://）のときだけ有効になるテストログインで行う
- 未決: SSO の接続先（Entra ID のテナント情報）→ N5 に着手前ゲート
