# ミッション: 紙と Excel の経費精算を Web 化する

- 仕様書: `docs/spec/expense-app.md`（この記入例では `docs/devkit/examples/expense-app/spec.md`）
- 統合ブランチ: `devkit/expense-app`

## 目的

申請・承認・経理の転記を Web 上で完結させ、承認待ちの滞留と転記ミスをなくす。

## 完了の定義（ミッションの goal）

1. graph のすべてのノード（N1〜N6）が done
2. `pnpm verify:full` が exit 0
3. AC-1〜AC-10 のすべてに、番号をテスト名に含むテストがある
4. 仕様書にない機能を追加していない

## 制約

- 標準技術スタックから外れない
- 会計システム・本番の SSO には接続しない（OIDC はテスト用の差し替えで確かめる）
- DB を読む画面は `src/app/(app)/` の下に置く（`next build` のときに DB へ接続しない）

## 前提

- 部署は1階層、部長は部署ごとに1人（利用者が「おまかせ」と回答）
- 認証用のテーブル・環境変数・利用者の型は N1 で決め、N5 はその形のまま接続する（自分の判断）

## 開始前の準備（承認後にメインセッションが行う）

- 追加する依存パッケージ: better-auth、date-fns、@date-fns/tz
- 変更する共有ファイル: なし

## 人間ゲート

| ノード | 種類   | 判断してほしいこと                                                    |
| ------ | ------ | --------------------------------------------------------------------- |
| N1     | after  | テーブル設計（特に approvals の持ち方と、users を Better Auth の user として使う形）でよいか |
| N5     | before | SSO の接続先（Entra ID のテナント）と、開発用のテストアカウントの用意 |

## 進め方

- 並列数 3、サイクル上限 8
- 見込み: 3段（N1 → N2/N3/N4/N5 → N6）、4〜5 サイクル

## 見張り（loop）

- 自走中: 席を外すときは `/loop 30m`
- PR 作成後: `/loop` で CI とレビューに対応
