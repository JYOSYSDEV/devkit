# ADR-0001: 社内標準の技術スタックと devkit の4層モデルを採用する

- 状態: 承認
- 日付: 2026-11-09

## 背景

Claude Code を使ったシステム開発を、特定の詳しい人に頼らず社内の誰でも進められるようにしたい。プロジェクトごとに技術スタックや進め方が違うと、AI の成功率も人のレビューの質もばらつく。

## 決定

1. 業務 Web アプリの標準技術スタックを `docs/devkit/stack.md` のとおりとする（Next.js + TypeScript + PostgreSQL/Drizzle + Vitest/Playwright + Biome）。
2. 開発は計画（graph）・goal・ランナー・人間ゲートの仕組み（`docs/devkit/model.md`）で進め、テンプレートに標準で組み込む。
3. 完了の判断は `pnpm verify` を基準とし、実装者とは別の評価エージェントが判定する。

## 検討した選択肢

| 選択肢                                                      | 良い点           | 悪い点                                               |
| ----------------------------------------------------------- | ---------------- | ---------------------------------------------------- |
| フロントとバックエンドを分ける（React + 別の API サーバー） | 大規模化しやすい | 部品と契約が増え、並列ノード間の不整合が起きやすい   |
| Prisma                                                      | 利用者が多い     | コード生成の手順があり、メジャー版ごとの変化が大きい |
| ESLint + Prettier                                           | 実績が長い       | 設定が2系統になる                                    |
| プロジェクトごとに自由に選ぶ                                | 柔軟             | 標準化の目的に反する                                 |

## 影響

- 標準外の技術を使う場合は ADR を書いて承認を得る。
- 別系統のスタック（例: モバイル、データ処理）は、4層の部分を流用して別のテンプレートとして作る。
